# 아이템 12종 — 설계

기획서 `2026-08-31-reroll-beasts-design.md` §8 을 실제 코드에 붙이는 설계다.
기획서가 비워 둔 것(드랍 시점 · 장착 조작 · 합성 처리 · 봇 취급)을 여기서 정한다.

## 1. 무엇을 만드나

- 아이템 12종. 완성품 직접 드랍, 조합표 없다
- 유닛당 3칸. 같은 아이템 중복 허용
- 런당 7개 지급. 지정된 라운드가 시작될 때 인벤토리에 하나 들어온다
- 인벤토리 아이콘을 판/벤치 유닛으로 **드래그**해 장착
- 한 번 끼우면 못 뺀다. 유닛을 팔면 아이템만 인벤토리로 돌아온다 (TFT 규칙)
- 봇도 같은 규칙으로 아이템을 받는다

기획서와 **다른 점 하나**: 기획서는 "PvE 라운드마다 1개"라고 썼는데
`rounds.json` 의 `pveRounds` 가 전 스테이지 빈 배열이다 — 23라운드 전부 PvP 다.
PvE 라운드를 만들지 않고, **정해진 라운드에 그냥 지급**한다.

## 2. 데이터 — `game/public/data/items.json`

```json
{
  "slotsPerUnit": 3,
  "grantRounds": ["1-2", "1-3", "2-2", "2-5", "3-3", "4-3", "5-3"],
  "items": [ ... 12종 ... ]
}
```

`grantRounds` 는 **라벨**이다. 절대 라운드 번호로 적으면 스테이지 구성이 바뀔 때
지급 시점이 소리 없이 다른 곳으로 옮겨 간다. 라벨 → 번호 변환은
`sim/rounds.js` 의 `grantIndices(data)` 가 `roundAt` 을 써서 한 번만 한다.

### 아이콘

`tools/item-icons.mjs` 로 16×16 PNG 12장을 찍는다 —
`tools/trait-icons.mjs` 와 같은 방식(픽셀 배열 + 팔레트).

출력은 `game/public/assets/ui/item_<id>.png`.

## 3. `sim/items.js` (신규)

`stats.js` 에 넣지 않는다. `stats.js` 는 이미 "티어×직업×성급 해석"과
"시너지 효과 병합" 두 가지를 하고 있고, 여기에 아이템까지 넣으면 세 주제가
한 파일에 산다.

```
itemById(itemsData, id)
applyItems(stats, itemIds, itemsData)   → 숫자 스탯이 반영된 새 객체
itemSpecials(itemIds, itemsData)        → 행동형 묶음
mergeSpecials(traitSpecials, itemSpecials) → 전투가 읽는 하나의 묶음
```

**적용 순서: `base → 시너지 → 아이템`.** 퍼센트는 계통별로 따로 곱한다.
시너지 공격력 +20% 와 강철검 +20% 가 붙으면 `1.2 × 1.2 = 1.44` 배다.
한 번에 더해 `1.4` 로 만들면 시너지 코드가 아이템을 알아야 한다.

**아이템은 개수만큼 더한다.** 화살촉 2개면 관통 2명, 가시갑옷 2개면 반사 40%.
시너지 쪽이 `pierceCount` 를 MAX 로 병합하는 것과 규칙이 다르다 —
시너지는 겹쳐도 하나의 효과지만 아이템은 칸을 하나 더 쓴 대가다.
`mergeSpecials` 는 시너지 값과 아이템 값을 **합**한다.

## 4. 전투 훅 — `sim/combat.js`

`buildCombatants` 가 `entry.items` 를 읽어 스탯과 특수 묶음을 만든다.

| 아이템 | 붙는 자리 |
|---|---|
| 관통 화살촉 | 기존 `pierceCount` 루프가 그대로 받는다. 새 코드 없음 |
| 가시 갑옷 | `strike()` 안. 공격자 사거리가 1일 때만 `floor(dealt × thornsPct/100)` 를 공격자에게 고정 피해. 로그 `thorns` |
| 흡혈의 낫 | `strike()` 안. `floor(dealt × lifestealPct/100)` 회복, `maxHp` 상한. 로그 `heal` |
| 승리의 깃발 | 전투 시작 블록. `dist ≤ auraRadius` 인 **아군**에게 `atkPct` 버프를 만료 없이 건다 |

- 반사는 **근접 평타만** 받는다. 스킬·지속피해·원거리는 반사되지 않는다
- 반사 피해는 반사를 다시 일으키지 않는다. 두 유닛이 마주 서면 무한 왕복이 된다
- 반사로 죽으면 기존 `sweepDeaths` 가 그 틱에 받는다
- 흡혈은 `hit.dealt` 를 곱한다. 요청 피해가 아니라 실제로 들어간 양이다 —
  HP 50 남은 적을 1000 으로 마무리하고 200 을 회복하는 일이 없다
- 오라는 `buffs` 에 `{ stat: 'atkPct', amount, expiresAt: Infinity }` 로 넣는다.
  `effectiveStat` 이 이미 `<key>Pct` 접미사를 읽는다. 새 경로가 없다
- 오라는 **전투 시작 시점의 인접**으로 고정한다. 매 틱 다시 계산하면 이동할
  때마다 공격력이 출렁이고 로그만으로 화면을 복원할 수 없다

로그에 `thorns` 한 종류가 는다. 리플레이(`game/src/battle.js`)가 이 타입을
모르면 조용히 무시하므로, 체력이 로그와 어긋난다 — 재생 쪽도 같이 붙인다.

## 5. 상태 — `sim/roster.js`

```
state.items = []              // 인벤토리. 아이템 id 배열, 상한 없음
유닛 칸 = { uid, unitId, star, items: [] }   // 최대 3
```

| 함수 | 규칙 |
|---|---|
| `grantItem(state, rng, itemsData)` | 12종 중 하나를 뽑아 인벤토리에 넣는다 |
| `equipItem(state, uid, invIndex, data)` | 3칸을 넘으면 거부. 성공하면 인벤토리에서 빠진다 |
| `sell` | 낀 아이템 전부 인벤토리로 돌아온다 |
| `resolveMerges` | 재료 3장의 아이템을 모아 자리 순서대로 최대 3개를 승급 유닛에 넘기고, 나머지는 인벤토리 |
| `toCombatEntries` | `{ unitId, star, tile, items }` |

`buy` 로 새로 산 유닛은 `items: []` 로 시작한다.

**드랍 RNG 는 별도 스트림이다.** `createRng(seed ^ 0x1737 ^ index)` 를 쓴다.
`run.rng` 에서 뽑으면 아이템 한 번 뽑을 때마다 상점 뽑기 순서가 밀려,
같은 시드로 저장해 둔 기존 결과가 전부 달라진다.

## 6. 지급 배선 — `game/src/main.js`

`settle()` 이 다음 라운드로 넘어간 직후, 그 라운드가 지급 라운드면
`grantItem` 을 부르고 `prep.show()` 한다. 첫 라운드(1-1)는 지급이 없다.
지급 라운드의 **시작**에 주므로 배치 시간 안에 끼울 수 있다.

## 7. 봇

`sim/lobby.js` 의 `botBoard` 가 라운드마다 판을 새로 짜므로, 같은 자리에서
아이템도 같이 정한다. 지금까지 지난 지급 라운드 수 = 봇이 가진 개수.
앞줄 유닛부터 3개씩 채우고, 아이템 종류는 `botBoard` 가 받은 rng 로 뽑는다.
따라서 같은 시드면 봇의 아이템도 같다.

## 8. UI

### 아이템 바 (`index.html` + `prep.js`)

좌하단 가로 줄. 보유 아이콘을 나열하고, 같은 아이템이 여럿이면 개수 뱃지를
붙인다. 없으면 줄 자체가 안 보인다.

### 장착 — 드래그

기존 배치 드래그의 `dropTargetAt` · `highlight` 를 재사용한다.
끌고 있는 것이 아이템이면 드롭 대상은 **유닛**이다(빈 칸 아님).
3칸이 찬 유닛 위에서는 빨간 표시를 내고 놓아도 아무 일이 없다.

### 판 위 표시 — 체력바 아래

`scene3d.js` 의 `makeBadge` 가 그리는 캔버스 스프라이트에 한 줄을 더한다.
현재 128×52(전투) / 128×20(배치) 인 캔버스 높이를 아이템이 있을 때 +18 하고,
그 줄에 16px 아이콘을 가운데 정렬로 최대 3개 그린다.

DOM 오버레이를 따로 띄우지 않는 이유: 배지가 이미 말 위에 붙어 따라다니고,
투영·가림 처리가 전부 끝나 있다. DOM 으로 하면 매 프레임 3D→화면 좌표 투영이
유닛 수만큼 늘고 390px 화면에서 겹친다.

아이콘 PNG 12장은 `prep.preload` 진행바에 얹어 미리 받는다. 로딩이 늦으면
배지가 빈 칸으로 한 프레임 그려진다.

### 유닛 정보 패널

기존 정보 패널에 낀 아이템 3칸을 붙인다. 아이콘 · 이름 · 효과 한 줄.

## 9. 검증

### `tools/validate.mjs` 불변식 추가

1. 아이템 id 가 유일하다
2. 모든 효과 키가 화이트리스트 안에 있다 (오타 난 키는 조용히 무시되어 효과 없는 아이템이 된다)
3. `grantRounds` 의 모든 라벨이 실재하는 라운드다
4. 아이콘 파일 `item_<id>.png` 12장이 전부 있다

### `tests/items.test.js`

- `applyItems` 수치 — 강철검이 공격력을 정확히 1.2배로 올린다
- 시너지와 아이템 퍼센트가 따로 곱해진다
- 같은 아이템 2개가 더해진다
- 3칸 초과 장착이 거부된다
- 판매하면 아이템이 인벤토리로 돌아온다
- 합성이 아이템을 승계하고 4개째부터 인벤토리로 보낸다
- 반사 · 흡혈 · 오라 · 관통이 전투 로그에 실제로 나타난다
- 반사가 반사를 부르지 않는다
- 같은 시드는 같은 아이템을 드랍한다
- 아이템 없는 보드의 전투 결과가 지금과 **똑같다** (기존 골든 로그 유지)

## 10. 밸런스 메모 (구현 후 `sim/run.mjs` 로 잰다)

- 거인의 심장 +400 은 1티어 1성 탱커(675 HP)에게 +59% 다. 큰 값이다
- 현자의 보주 +30 은 1티어 1성 마법사(42 power)에게 +71% 다. 더 크다
- 둘 다 고정값이라 저티어·저성급일수록 강하다. 티어 비례로 바꿀지는
  헤드리스 러너로 승률을 재고 나서 정한다. 이번 작업에서는 기획서 값 그대로 간다
