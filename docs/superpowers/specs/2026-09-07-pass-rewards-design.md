# 시즌 패스 보상 — 설계

25단계 트랙을 실제 보상으로 채운다. 지금은 **보상이 있는 칸이 넷**뿐이다.

## 1. 왜 지금 이걸 하나

트랙은 섰고(`2026-09-03-home-lobby-design.md` §9 의 4번), 결제도 붙었고, 미션이
경험치를 버는 두 번째 길까지 냈다. 그런데 정작 **올라가서 받을 것이 없다.**

지금 25단계에 걸린 것:

- 아바타 2개(10단계 닌자 · 22단계 해골), 무대 1개(15단계), 이펙트 1개(18단계)
- 무료 젬은 5단계마다 25 — 다섯 번뿐이다
- 나머지 21칸은 **프리미엄을 산 사람에게만** 젬 40이 뜨고, 안 산 사람에게는 빈칸이다

트랙을 열어 본 사람이 "여기 뭐가 있지" 하고 스크롤하다 빈칸 스무 개를 지나면,
그 화면은 진열대가 아니라 **비어 있다는 증거**가 된다. 패스 경험치를 버는 경로를
아무리 늘려도 도착지가 비어 있으면 올라갈 이유가 없다.

## 2. 범위

**포함**

- 무료 트랙: **매 단계 젬**(10) + 5의 배수마다 추가(15). 빈칸이 사라진다
- 큰 보상 12개: 기존 4 + **신규 8**(무대 3 · 이펙트 3 · 아바타 2)
- 신규 8개 중 **4개는 프리미엄 전용** — 산 사람이 남이 안 가진 것을 갖는다
- 프리미엄 전용을 위한 해금 규칙 한 줄(`passTrack`)
- 트랙 화면이 무대·이펙트 보상도 그린다(지금은 아바타만 그린다)

**제외**

- 새 아바타 모델 반입. 구워 둔 20개 중 18개가 이미 쓰이고 **남은 것이 둘**이다.
  원본 캐릭터 팩(`q-ultimate-characters`)은 저장소에 없다 — 새로 넣으려면 팩부터
  구해야 하고, 그건 이 조각보다 크다
- 패스 보상을 젬으로 앞당겨 사기. `shop.sellUnlock` 이 `gem` 이라 패스 보상은
  값이 없다(`priceOf` 가 null). **그대로 둔다** — 돈으로 같은 것을 얻으면 트랙을
  도는 이유가 사라진다
- 시즌 2 표. 시즌이 갈릴 때 무엇을 갈아 끼우는지는 그때 정한다

## 3. 보상표

### 3.1 젬

| 트랙 | 규칙 | 시즌 총합 |
|---|---|---|
| 무료 | 매 단계 10, 5의 배수엔 +15 | 325 |
| 프리미엄 | 매 단계 40 | 1,000 (지금과 같다) |

무료를 125 → 325 로 올린다. 젬 상점의 최소 묶음이 300젬/$0.99 이므로 한 시즌
(약 3개월) 무료 보상이 대략 1달러어치다 — 젬을 파는 이유를 없애지 않으면서,
매 단계 받을 것이 생긴다. 젬 아바타는 120~260젬이므로 **한 시즌을 끝까지 돌면
그중 무엇이든 하나**는 살 수 있다. 그게 다음 시즌에도 돌 이유가 된다.

## 4. 규칙 — 프리미엄 전용을 어떻게 잠그나

`cosmetics.json` 의 패스 보상 줄에 칸 하나를 더한다.

```json
{ "id": "voidstone", "unlock": "pass", "passLevel": 9, "passTrack": "premium", ... }
```

`passTrack` 이 없으면 `free` 로 친다 — 기존 네 줄을 안 고쳐도 지금과 같이 동작한다.

`sim/cosmetics.js` 의 `isUnlocked` 에 규칙이 한 줄 는다:

```js
if (item.unlock === 'pass') {
  const reached = (owned.passLevel ?? 0) >= (item.passLevel ?? 0)
  // 프리미엄 트랙은 단계만으로 안 열린다. 안 그러면 안 산 사람도 다 갖는다.
  return reached && (item.passTrack !== 'premium' || !!owned.premium)
}
```

**`owned` 를 만드는 자리가 셋이다** — 서버의 `updateLook`·`buyCosmetic`,
클라의 `ownedNow`. 셋 다 `premium` 을 넣어야 한다. 하나만 빠뜨리면 그 경로에서만
프리미엄 보상이 잠긴 채로 보이고, 화면과 서버가 다른 답을 낸다.

**해금 단계의 단일소스는 계속 `cosmetics.json` 하나다.** `pass.json` 에는 젬
규칙만 있고, 트랙 화면은 코스메틱을 **읽어서** 만든다(지금 규칙 그대로).

## 5. 트랙 화면

`passTrack(data, pass)` 가 지금은 아바타만 훑는다. 무대·이펙트까지 훑고 트랙별로
가른다. 한 줄의 모양:

```js
{
  level,
  reached,          // 내 단계가 여기까지 왔나
  free:    { gems, item },   // item: { kind:'avatar'|'board'|'boom', id, name, file?, colors?, fx? } | null
  premium: { gems, item },
}
```

화면은 종류마다 다르게 그린다:

- **아바타** — 지금처럼 초상(파일에서 찍은 그림)
- **무대** — 색 네 개를 가로 띠로. 판 견본을 찍으면 25칸을 여는 순간 프레임이
  끊긴다(꾸미기 창은 캐시가 있지만 트랙은 한 번에 스물다섯이다)
- **이펙트** — 그 색의 원 하나. 이펙트는 움직여야 뜻이 사는데 25칸을 동시에
  움직이면 화면이 시끄럽다. 색만 보이고, 자세한 것은 꾸미기 창에서 본다

프리미엄 줄은 **안 산 사람에게도 보인다.** 무엇을 놓치고 있는지 안 보이면 살
이유가 생기지 않는다 — 지금 트랙이 이미 그렇게 하고 있다(잠긴 단계도 전부 그린다).

## 6. 검증

| 무엇 | 어디서 |
|---|---|
| 프리미엄 전용은 단계에 닿아도 안 사면 안 열린다 | vitest |
| 프리미엄을 사면 그 단계에서 열린다 | vitest |
| `passTrack` 이 없으면 무료로 친다 (기존 줄 호환) | vitest |
| 젬 총합: 무료 325 · 프리미엄 1,000 | vitest |
| 트랙 25줄에 **빈 줄이 없다**(젬이든 물건이든) | vitest |
| 무대·이펙트 보상이 트랙에 뜬다 | vitest |
| 서버가 프리미엄 전용을 검산한다(안 산 사람이 고르면 기본값으로) | 서버 테스트 |
| 트랙 화면의 세 가지 그림 | 브라우저 |

불변식(`tools/validate.mjs`)에 넉 줄 추가한다.

- 패스 보상의 `passLevel` 이 1..`maxLevel` 안이다
- `passTrack` 은 `free`·`premium` 둘 중 하나다(없으면 무료)
- **같은 단계·같은 트랙에 큰 보상이 둘 이상 걸리지 않는다** — 한 칸에 둘이면
  화면이 하나만 그리고 나머지는 조용히 사라진다
- 아바타 보상의 `file` 이 실재한다. 없는 파일이면 트랙에 빈 액자가 뜬다
