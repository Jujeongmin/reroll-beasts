# 설정 · 항복 · 계정 초기화 — 설계

설정 창을 만든다. **홈과 인게임 양쪽에서 열린다.** 인게임에는 항복이 붙는다.

이건 세 조각 중 첫 번째다. 나머지는 §7.

## 1. 왜 지금 이걸 하나

지금 게임에는 **나가는 길이 없다.**

판에 들어가면 23라운드를 다 돌거나 죽을 때까지 화면이 안 바뀐다. 그만두려면
새로고침뿐인데, 그러면 서버 쪽 방은 **내가 살아 있는 줄 알고 계속 돈다** — 남은
일곱이 유령과 대진을 잡고, 그 판은 내 좌석이 마감 때마다 빈 판으로 지는 것으로
처리된다. 나간 사람에게도 나쁘고 남은 사람에게도 나쁘다.

설정도 없다. 소리·언어·움직임 같은 것을 고칠 자리가 아예 없고, 계정을 처음부터
다시 하고 싶어도 방법이 없다.

## 2. 범위

**포함**

- 설정 창 하나(`game/src/settings.js`). **홈과 인게임이 같은 창을 연다**
- 인게임에서만 보이는 **항복**. 서버가 좌석을 죽이고 순위를 박는다
- **계정 초기화** — 기기 저장 + 서버 프로필. 확인 두 단계
- **움직임 줄이기** — 저장하고, 승급 연출·로딩 걷기가 그 값을 본다
- 언어·소리 칸은 **잠긴 채로** 자리만. 왜 잠겼는지 한 줄 적는다

**제외**

- 오디오 시스템 (조각 B). 볼륨 손잡이가 닿을 곳이 아직 없다
- 한국어·영어 (조각 C). UI 문자열이 전부 하드코딩이라 이 조각보다 크다
- 전투 배속 · 그래픽 품질 · 알림. §6

## 3. 설정 창

한 벌만 만든다. 두 벌로 만들면 항목 하나 늘 때마다 두 군데를 고치고, 그러다
한쪽만 고친 상태가 남는다.

```
createSettings({ onSurrender, onReset, onMotion, ... })
  → { open({ inGame }), close() }
```

`open({ inGame: true })` 면 항복 줄이 보인다. 그것 말고는 두 화면이 같다.

**여는 자리**

- 홈: 좌측 아래 `아바타 고르기`·`젬 상점` 옆에 `설정`
- 인게임: 우측 아래 `#hudR`, 상점 잠금 버튼 옆에 톱니 하나

인게임 버튼을 **오른쪽 아래**에 두는 이유: 왼손 엄지가 닿는 곳(좌측)은 배치와
상점이 쓴다. 오른쪽 끝은 이미 잠금 버튼이 쓰는 "판과 무관한 스위치" 자리다.

### 3.1 항목

| 항목 | 지금 | 저장 |
|---|---|---|
| 소리 — 효과음·배경음 | **잠김**("소리는 다음 조각에서 붙는다") | — |
| 언어 — 한국어/English | **잠김**("영어는 다음 조각에서 붙는다") | — |
| 움직임 줄이기 | 켜고 끈다 | `rr.motion` |
| 내 계정 | 지갑 주소 꼬리 4자 | — |
| 데이터 초기화 | 두 단계 확인 | — |
| **항복** (인게임만) | 두 단계 확인 | — |
| 버전·출처 | 한 줄 | — |

설정은 **기기 저장**이다. 계정에 두면 값 하나 바꿀 때마다 서버 왕복이 필요하고,
볼륨·움직임은 기기마다 달라도 되는 값이다(폰에서는 소리를 끄고 PC에서는 켠다).

## 4. 항복

**서버가 판정한다.** 클라가 화면만 닫으면 방은 그대로 돌고, 남은 사람들은 유령과
대진을 잡는다.

### 4.1 규칙 — `sim/lobbyRound.js`

```js
concede(state, account)  // → { changed, seatId }
```

그 계정의 좌석을 찾아 `hp = 0`, `alive = false` 로 만든다. 이미 죽었거나 없는
계정이면 `changed: false`. **순위는 여기서 안 박는다** — `assignRanks` 가 그
일을 하고, 서버가 이어서 부른다(마감이 쓰는 그 흐름 그대로다).

죽이기만 하고 라운드를 안 넘기는 이유: 항복은 마감이 아니다. 남은 사람들의
라운드는 그들의 시각으로 흘러야 한다.

### 4.2 서버 — `surrender()`

방 락 안에서 `concede` → `assignRanks` → 전적·미션·패스 반영(`resolveRound` 가
쓰는 그 블록과 같은 함수들) → 방 상태 저장 → `ROUND_RESOLVED` 방송.

**정산을 같이 하는 이유**: 항복도 그 사람의 판이 끝난 것이다. 순위만 박고
전적을 안 남기면 "8위로 끝난 판"이 전적에 안 잡히고, 그게 곧 항복으로 기록을
피하는 길이 된다.

중복 정산은 이미 있는 장치가 막는다 — `countedMatch(profile, matchId)` 가
같은 판을 두 번 세지 않는다.

### 4.3 화면

항복하면 홈으로 돌아간다. 결과 화면을 거치지 않는다 — 내가 끝낸 판이라
"졌습니다"를 다시 보여 줄 이유가 없다.

확인은 두 단계다: `항복` → "이 판이 끝난다. 순위는 지금 자리로 기록된다" → `항복한다`.

## 5. 계정 초기화

**되돌릴 수 없다.** 그래서 무엇이 사라지는지 이름으로 적고, 두 번 누르게 한다.

### 5.1 지우는 것

- 기기: `rr.avatar` · `rr.board` · `rr.boom` · `rr.tutorial.done` · `rr.name.ask` · `rr.motion`
- 계정(서버): 프로필 통째 — 전적 · LP · 젬 · 패스 · 산 코스메틱 · 닉네임 · 미션

### 5.2 서버 — `resetAccount()`

계정 락 안에서 `updateUserState(account, { profile: null })`. 순위표 줄도 지운다 —
안 지우면 전적은 0인데 순위표에는 옛 LP 가 남는다.

**결제 기록(`purchases` 컬렉션)은 안 지운다.** 그건 영수증이다. 지우면 같은
결제가 다시 들어올 때 "처음 보는 결제"로 읽혀 두 번 지급된다. 대신 프로필이
비므로 **산 코스메틱과 프리미엄 패스도 함께 사라진다** — 확인 문구에 그 사실을
적는다.

### 5.3 확인 흐름

1. `데이터 초기화` 를 누른다
2. "**전적 · 젬 · 패스 · 산 아바타 · 닉네임**이 전부 사라진다. 되돌릴 수 없다."
3. `지운다` / `그만두기`

문구 입력(“DELETE”를 타자)까지는 안 시킨다 — 이 게임의 계정은 무료로 다시 만들
수 있는 것이고, 그 마찰은 실수보다 짜증을 더 만든다.

지운 뒤에는 화면을 다시 띄운다(`location.reload`). 남은 상태를 손으로 하나씩
되돌리는 것보다 확실하다 — 튜토리얼을 끝냈을 때 이미 쓰는 방식이다.

## 6. 움직임 줄이기

`rr.motion` 에 `'full' | 'reduced'` 를 적는다. 값이 없으면 **`prefers-reduced-motion`
을 따른다** — 기기가 이미 답한 질문을 다시 묻지 않는다.

이 값을 보는 곳:

- 승급 연출 (재료 빨려듦·폭발·펀치) — 끄면 별 강조만 남긴다
- 로딩 화면의 걷는 말
- 짚은 자리 파문

**끄지 않는 것**: 전투 애니메이션·투사체. 그건 연출이 아니라 무슨 일이 벌어지는지
말하는 정보다. 끄면 화면이 무슨 일인지 못 읽게 된다.

읽는 자리가 여럿이라 `sim` 이 아니라 화면 쪽 작은 모듈(`game/src/settings.js`)이
값을 쥐고, 필요한 곳에서 그 함수를 부른다.

| 무엇 | 어디서 |
|---|---|
| `concede` 가 좌석을 죽인다 · 없는 계정·이미 죽은 좌석은 안 바꾼다 | vitest |
| 항복한 좌석에 순위가 박힌다 | vitest |
| 항복이 전적을 남긴다 · 같은 판을 두 번 안 센다 | 서버 테스트 |
| 초기화가 프로필과 순위표 줄을 지운다 · 결제 기록은 남는다 | 서버 테스트 |
| 설정 창이 홈·인게임 양쪽에서 열린다 · 항복은 인게임에서만 | 브라우저 |
| 움직임을 끄면 승급 연출이 조용해진다 | 브라우저 |
