# 홈 로비 — 설계

메인화면을 "모드 버튼 세 개"에서 **로비**로 바꾼다. 연습 모드를 없애고,
서버 접속을 필수로 만들고, 새 UI 팩으로 갈아입힌다.

이건 더 큰 작업의 **첫 조각**이다. 전체는 §9 에 적었다.

## 1. 왜 지금 이걸 하나

지금 홈은 무대 위에 뜬 오버레이 하나에 버튼 셋(일반·랭크·연습)이다. 게임을
고르는 창구지 로비가 아니다. 앞으로 붙을 것들 — 튜토리얼, 전적, 패스, 상점 —
이 전부 이 화면에 매달리는데, 지금 골격에는 그것들이 앉을 자리가 없다.

그래서 화면을 먼저 세운다. 자리가 없으면 기능을 붙일 때마다 화면을 다시 짠다.

## 2. 범위

**포함**

- 좌측 세로 패널 로비 골격 (일반/랭크 메뉴 + 전적 + 접속 상태)
- 연습 모드와 로컬 봇 로비 **삭제**. 서버 접속 실패는 실패로 끝난다
- 최소 프로필: 판수 · 1위 횟수 · 최고 순위 · 최근 5판 순위. **서버가 기록한다**
- 새 UI 에셋 (Kenney UI Pack RPG Expansion, CC0)
- 홈 전용 배경(SVG 레이어) + 간판 캐릭터 + 시즌 패스 **자리**
- 홈 로직을 `game/src/home.js` 로 분리

**제외** (다음 조각들)

- 튜토리얼 — 메뉴 버튼도 이번엔 안 넣는다. 동작 없는 버튼은 거짓말이다
- LP · 티어 · 시즌 · MMR
- 코스메틱 · 패스 **내용** · 상점 · 결제. 자리만 잡고 눌리지 않게 둔다 —
  진열대를 열어 두고 안이 비어 있으면 그게 더 나쁘다
- 배치·전투 화면의 UI 교체 (홈만 새 팩을 쓴다. §7 참고)

## 3. 화면 골격

기준 판 812×390 (가로 폰).

**배경은 홈이 따로 짓는다.** 처음에는 무대(3D)를 그대로 비춰 쓰려 했는데,
그러면 로비가 "게임 화면을 흐려 놓은 것"으로 읽히고 라운드 중에 홈으로
돌아온 것 같은 착각을 준다. 그래서:

- 인라인 SVG 레이어 — 달·별·능선 두 겹·안개, CSS 불티 몇 점. 사진 한 장을
  깔면 화면 폭이 700~1040 사이에서 변할 때마다 다른 데가 잘린다
- 간판 캐릭터: 3성 드래곤 모델을 부팅 때 한 번 크게 찍어 건다
  (`prep.heroPortrait`). 2D 일러스트를 따로 그리면 모델을 바꿀 때 어긋난다
- 오른쪽 아래에 **시즌 패스 자리**. 팔 물건(코스메틱)이 아직 없어 잠겨 있다

```
┌──────────────┬────────────────────────────────┐
│ REROLL       │  ☾                 [접속 상태] │
│ BEASTS       │        ╭──────╮                │
│              │        │ 드래곤│                │
│ [ 일반 매치 ]│        ╰──────╯   ┌──────────┐ │
│ [ 랭크 매치 ]│   ~~능선~~~~~~~~~ │ 시즌 패스 │ │
│              │                   │  준비 중  │ │
│ 전적 12판    │                   └──────────┘ │
│ 최고 1위     │                                │
│ 3·5·1·8·2    │                                │
└──────────────┴────────────────────────────────┘
   152px
```

- 무대 카메라를 오른쪽으로 밀어 패널에 안 가리게 한다
- **대기열은 패널 안에서 메뉴를 대체한다.** 대기 중에는 메뉴가 사라지고
  `일반 대기 3/8 · 12초` + `취소` 가 그 자리를 차지한다. 상태가 바뀌면 화면도
  바뀌어야 지금 무엇을 하는 중인지 안 헷갈린다. 지금처럼 버튼 아래 한 줄로
  덧붙이면 "누를 수 있는 것"과 "기다리는 중"이 한 화면에 공존한다

### 3.1 세 가지 상태

홈은 아래 셋이 **전부 화면으로 성립해야** 한다. 하나라도 비면 그 상태에 빠진
사람은 멈춘 화면을 본다.

| 상태 | 메뉴 | 전적 | 안내 |
|---|---|---|---|
| 접속 중 | 보이되 눌리지 않음 | 빈칸 | `서버에 붙는 중…` |
| 접속 실패 | 눌리지 않음 | 빈칸 | 사유 + `다시 시도` |
| 접속됨 | 열림 | 채움 (기록 없으면 `첫 판을 기다린다`) | 없음 |

**실패 사유를 뭉뚱그리지 않는다.** 인증이 없는 로컬 실행은 서버 장애와 다르다
(§8). `?auth=` 가 없으면 `로컬 실행 — 인증이 없어 서버에 못 붙는다` 라고
정확히 말한다. "서버 오류"라고만 하면 개발 중 매번 헛다리를 짚는다.

## 4. 코드 경계

지금 홈 로직은 `main.js` 안에 100줄쯤 인라인이다. 여기에 패널·프로필·대기열
상태까지 얹으면 `main.js` 가 부팅 · 화면 전환 · 라운드 진행 **에다** 홈까지 쥔다.

```
game/src/home.js   (신설)  홈 화면만 안다
game/src/main.js   (수정)  "홈이 모드를 골라 줬다" 만 받는다
game/src/matchmaker.js     삭제
```

`createHome({ data, onPick })` — `onPick(mode)` 로 `'normal' | 'ranked'` 를 낸다.

**홈은 매치메이커를 모른다.** 서버 접속과 큐는 `main.js` 가 계속 쥐고, 홈에는
상태만 밀어 넣는다(`setStatus`, `setProfile`, `setQueue`). 홈이 SDK 를 알면
홈 테스트가 네트워크에 묶인다.

## 5. 연습 제거

- `game/src/matchmaker.js` (109줄, `createLocalMatchmaker`) 삭제
- `main.js` 의 try/catch 폴백 삭제 — 접속 실패는 홈의 실패 상태로 끝난다
- `serverMatchmaker.js` 의 `roomId = null` 경로(`joinLobby`, 봇 7 방)는 **남긴다.**
  서버에 이미 있는 함수이고, 다음 조각의 튜토리얼이 그 위에 설 수 있다

**잃는 것**: 서버 없이 게임을 돌려 보는 길이 사라진다. 그래서 §8 의 검증 층이
갈린다. 이건 감수하기로 한 비용이다 — 봇과 붙으면서 사람과 붙는 줄 아는 것보다
"서버에 못 붙었다"고 듣는 편이 낫다.

## 6. 최소 프로필

### 6.1 누가 쓰나 — 서버다

클라가 "나 1등"이라고 올리면 조작이 된다. 서버는 이미 로비 상태(체력·생존)를
쥐고 있으니, **좌석이 죽는 그 자리에서** 순위를 매겨 기록한다.

`resolveRound()` 안에서 체력이 0 이 된 좌석을 처리할 때:

- 죽은 좌석의 순위 = (처리 후 남은 생존자 수) + 1
- 한 라운드에 둘이 같이 죽으면 **둘 다 같은 순위**. 동시에 죽었으니 가를 근거가 없다
- 마지막 하나가 남으면 1위로 기록한다
- **봇 좌석은 건너뛴다.** 계정이 없다

순위 계산은 `sim/lobbyRound.js` 에 순수 함수 `rankOnDeath(state, before)` 로 넣는다.
서버 안에서 즉석으로 세면 테스트가 못 덮는다 — 마감 30초를 기다려야 검사되는
규칙은 테스트가 안 덮는다는 이 저장소의 원칙 그대로다.

### 6.2 저장

`$global.updateUserState(account, { profile })`. `pendingRoom` 을 이미 쓰고 있는
그 자리다. 새 컬렉션을 파면 정리 주체가 애매해진다.

```json
{
  "games": 12,
  "wins": 2,
  "best": 1,
  "recent": [3, 5, 1, 8, 2]
}
```

`recent` 는 최근 5판, 새 것이 앞. 6번째는 버린다 — 홈에 다섯 개만 보인다.

### 6.3 읽기

서버 함수 `getProfile()` 하나. 홈이 접속 직후 **한 번만** 부른다. 홈에 머무는
동안 값이 바뀔 일이 없다(내 판이 끝나야 바뀌는데, 그때는 홈에 없다).

기록이 없으면 `null` 을 준다. 0 으로 채운 표를 만들지 않는다 — `0판 · 최고 0위`
는 거짓 정보다.

## 7. UI 에셋

**Kenney UI Pack RPG Expansion (CC0)** — 양피지·가죽·금박. 지금 배치 화면의
나무 프레임과 같은 계열이라, 홈만 갈아입혀도 두 화면이 하나로 읽힌다.

- 원본은 `art-src/kenney-ui-pack-rpg-expansion/` 에 그대로 둔다 (다른 팩과 같은 자리)
- `tools/` 의 재단 스크립트가 **홈에서 실제로 쓰는 것만** `game/public/assets/ui/`
  로 뽑는다: 패널 프레임 1 · 버튼(기본·눌림) 2 · 구분선 1 · 배지 1. 팩 전체를
  복사하지 않는다
- 9-slice 는 지금 쓰는 방식 그대로(`border-image-slice`). 새 프레임도 같은 배선
- `CREDITS.md` 표에 줄 추가, `licenses/` 에 라이선스 전문. 이 저장소 규칙이다

배치·전투 화면은 이번에 안 건드린다. 같은 계열 팩이라 섞여도 안 튄다.

## 8. 검증

레퍼런스 게임(`verse8.io/b4F2E3N`)을 열어 확인한 것:

게임은 iframe 안에서 돌고, 플랫폼이 **account 와 서명된 auth 를 URL 로 주입**한다
(`…verse8.games/index.html?…&account=0x…&auth=<서명>&version=…`). 우리 로컬
dev(`localhost:5180`)에는 그게 없어서 SDK 가 익명으로 붙고 `connect()` 가 끝나지
않는다. **우리 코드나 배포의 결함이 아니라 인증이 없어서다.**

그래서 검증이 두 층으로 갈린다.

| 무엇 | 어디서 | 어떻게 |
|---|---|---|
| 홈 레이아웃 · 에셋 · 3상태 전이 | localhost | 서버 없이 그려진다. 눈으로 + 스크린샷 |
| 프로필 표시 · 대기열 · 매치 | 배포본 (verse8 iframe) | 배포 후 확인. 로컬에선 원리적으로 불가 |
| 순위 계산 규칙 | vitest | `sim/` 순수 함수. 돌연변이로 검증 |

3상태를 화면으로 만든 덕분에 로컬에서도 홈 작업이 끝까지 진행된다.

`npm run check` 는 계속 초록이어야 한다.

## 9. 이 조각 다음

| # | 조각 | 왜 이 순서 |
|---|---|---|
| 1 | **홈 로비 + 새 UI + 연습 제거** ← 이 문서 | 나머지 전부가 이 화면에 붙는다 |
| 2 | 튜토리얼 (스크립트된 짧은 판, 첫 실행 자동 + 홈 버튼) | 서버 없이 도는 경로 |
| 3 | 서버 계정 프로필 확장 (랭크·시즌) | 패스 진행도가 같은 저장소에 얹힌다 |
| 4 | 코스메틱 정의 + 보상 트랙 | 팔 물건이 있어야 패스가 성립 |
| 5 | VXShop 결제 배선 (`@verse8/platform`, `$onItemPurchased`) | 위가 서야 붙일 대상이 있다 |

**패스의 제약**: 지금 이 게임엔 코스메틱이 0 이다. 유닛·아이템은 전부 밸런스라
팔면 pay-to-win 이 된다. 그래서 4번(줄 물건 정의)이 5번보다 먼저다.

**결제는 만드는 게 아니라 붙이는 것**이다. `@verse8/platform`(VXShop)이 상품과
결제창을 쥐고, 서버는 `$onItemPurchased(data)` 훅으로 받는다. 아직 설치 안 됐다.
