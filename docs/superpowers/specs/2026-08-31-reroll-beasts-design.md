## 3. 보드 · 화면

### 3.1 보드

- 한 진영 = **4행 × 7칸 = 28칸**. 전투 시 총 8행 56칸
- 행마다 반 칸씩 어긋난 **헥스 오프셋 격자** (`rowOffset` 0/0.5 교대)
- **내 진영 화면 아래, 적 진영 화면 위**
- 최대 인구 9명 (= 레벨). 여유 19칸이므로 배치 전략이 성립한다

행 폭을 7로 통일한 이유가 있다. 좌우 대칭(반사)으로 진영을 대응시키면
가운데 두 행의 오프셋이 같아져 **마주 보는 앞줄이 항상 정렬**되고, 교전선에서
벌집이 맞물리지 않는다. 폭이 균일하고 오프셋이 교대하면 이 문제가 사라진다.

진영 대응은 반사가 아니라 **180° 회전**이다 — 행과 열을 함께 뒤집는다.
내 보드를 그대로 돌려 상대를 마주 보는 형태이고, 이래야 A로 저장한 스냅샷을
B로 불러와도 같은 진형이 나온다 (§10 의 전제).

### 3.2 렌더 — 3D

2D 스프라이트를 버리고 **three.js + glTF** 로 간다. 세 가지가 동시에 해결된다:

1. 옆모습 스프라이트는 상하 대치에서 위·아래를 볼 수 없다 (3D 는 실제 회전)
2. 반사 대응이 강제하던 진형 정렬 문제가 없다
3. 카메라 각도로 오토체스·TFT 의 시점을 그대로 낼 수 있다

에셋은 Quaternius **Ultimate Monsters** (CC0) 26종 + 진화 모델 6종,
보드는 KayKit **Medieval Hexagon Pack** (CC0). 비용 0.

### 3.2.1 화면은 하나다

배치와 전투가 **같은 화면**이다. 무대(판·카메라·조명·대기석)를 그대로 두고
상태만 바꾼다 — 전투가 "다른 화면으로 넘어가는 일"이 아니라 "그 자리에서
시작되는 일"이 되어야 한다.

| | 배치 | 전투 |
|---|---|---|
| 상대 절반 | 어둡게 눌림 | 밝힘 (거기에도 말이 선다) |
| 내 칸 테두리 | 청록으로 켬 | **계속 켬** — 난전에서는 어느 쪽이 내 진영인지 말만 보고는 안 읽힌다 |
| 카메라 | 판 + 대기석 | **똑같다** — 전투가 시작될 때 화면이 튀면 안 된다 |
| 하단 바 | 상점 5칸 | **그대로 상점** — 싸우는 동안에도 굴린다 (TFT 와 같다) |
| 무대 위 말 | 내 배치 + 상대 대기석 미리보기 | 로그의 spawn 이 세운 양 진영 |
| 판 조작 | 끌어서 배치 | **막힘** — 전투 중 말을 옮기면 재생 중인 로그와 어긋난다 |
| 재생 조작 | — | **배속 하나만.** 무대 위에 띄운다 |
| 끝났을 때 | — | 1.5초 보여주고 **스스로** 정산으로 넘어간다 |

전투 중 산 말은 **벤치로만** 들어온다. 전투는 시작 시점의 판으로 이미 계산된
로그이므로, 판 위 말이 도중에 바뀌면 화면이 그 로그와 어긋난다. 합성이 걸리면
상태에는 즉시 반영되지만 판에는 전투가 끝난 뒤에 나타난다.

일시정지·스크럽은 뺐다. 전투를 관람물로 만드는 조작인데, 전투 중에도 상점을
굴려야 하므로 손이 그쪽에 있어야 한다. 끝나고 확인 버튼을 누르게 하면
매 라운드 한 번씩 의미 없는 클릭이 쌓인다 — 그래서 스스로 넘어간다.

`scene3d` 가 무대를 만들고 `prep`·`battle` 이 나눠 쓴다. `battle` 은 씬을
**만들지 않고 받는다** — 각자 만들면 조명·안개·카메라가 미묘하게 어긋난다.

### 3.3 화면 (가로 812×390 기준)

TFT 배치를 따른다. **판이 화면의 주인이고 HUD 는 그 위에 뜬다.**
세로가 390px 뿐이라 상단 바와 벤치를 띠로 쌓지 않는다 — 쌓으면 그 높이만큼
판이 그대로 줄어든다.

```
배치                                       전투
┌──────────────────────────────────┐      ┌──────────────────────────────────┐
│▌1-1▐ ●●○○○          ♥40   3 / 6 │ 30px │ 라운드 3-2 · 상대 8기     3 vs 5 │ 오버레이
│┌────┐                            │      │                                  │
││시너│   [상대 4행 — 어둡게]       │      │   [8행 전체 · 진영별 색조]        │
││지  │   ────────────────         │      │                                  │
││바  │   [내 4행 — 청록 테두리]    │      │                                  │
│└────┘                            │      │                                  │
│      ⬡⬡⬡⬡⬡⬡⬡⬡⬡ 벤치 9칸        │ 46px │                                  │ 오버레이
├──────────────────────────────────┤      ├──────────────────────────────────┤
│(Lv) [카드 5장] [리롤](골드) [전투]│ 76px │ [재생][처음부터][스크럽][배치로] │
└──────────────────────────────────┘      └──────────────────────────────────┘
```

- **판 전체를 그린다.** 배치 때 상대 절반을 숨기면 판이 커지는 대신
  "어느 쪽이 내 자리인가"가 색으로 안 읽힌다. 대신 상대 절반을 어둡게 누른다
- **내 칸에는 청록 육각 테두리**를 얹는다. 타일 색을 밀면 머티리얼을 공유하는
  56칸이 같이 변하고, 지형 텍스처도 죽는다. 드래그 목표 칸만 테두리를 밝힌다
- 골드·경험치는 하단 양 끝의 **원형 디스크** (TFT 와 같은 자리). 경험치 디스크가
  곧 구매 버튼이다
- 상단 **가운데**에 배너 라운드 번호 + **스테이지 트랙**(이번 스테이지의 라운드
  점열, 네모는 PvE). 체력·인구는 오른쪽 끝
- 시너지는 좌측 세로 컬럼에 **육각 배지 + 등급색**(동·은·금). 전용 아이콘이 없어
  배지 안에는 시너지 이름 첫 글자를 넣는다 — 글자가 곧 표식이다
- 상점 카드는 TFT 구조다: 초상화 / 시너지 한 줄 / **티어색 이름띠** / 우상단 가격.
  티어색이 테두리·이름띠·후광에 같이 걸려 값이 한눈에 읽힌다
- 말을 탭하면 **닿는 칸이 호박색**으로 켜진다. 헥스 거리는 인접 홉 수이므로
  `sim/hex` 의 `dist` 를 그대로 쓴다 — 시야 좌표의 유클리드 거리로 재면
  화면의 사거리와 실제 사거리가 달라진다. 테두리는 상대 진영 칸에도 만들어 두고
  평소엔 숨긴다: 원거리 사거리는 교전선을 넘어간다
- **말은 모델을 먼저 레이캐스트해 집는다.** 칸 평면만 재면 몸통을 눌러도 그 뒤
  칸이 잡혀, 발밑을 정확히 겨눠야만 집히는 조작이 된다
- 시너지 행에 **손을 올리면** 상세가 뜬다: 단계별 효과와 구성 유닛.
  아직 못 구한 유닛은 회색 + 어두운 바탕, 보유한 유닛은 금테 + 밝은 바탕.
  효과 문구도 `traits.json` 의 **수치에서 만든다** (`game/src/trait-info.js`) —
  효과 키가 27종이라 표를 두고, 테스트가 모든 시너지의 모든 단계를 훑어
  문장을 못 만든 키를 잡는다
- 상단은 라운드 번호 + 스테이지 트랙(PvE 는 **마름모**) + 다음 상대 표기,
  체력·인구는 **숫자 + 막대**. 숫자만으로는 얼마나 남았는지가 안 읽힌다
- 말을 탭하면 우측에 정보 패널이 뜬다: 스탯 8종 · 스킬 · 판매가.
  스킬 설명은 `units.json` 의 **파라미터에서 만든다** (`game/src/unit-info.js`) —
  설명문을 따로 적어 두면 수치를 고칠 때 두 곳을 맞춰야 하고 언젠가 어긋난다
- 카메라 거리는 상수가 아니라 **그려진 타일을 실제로 투영해** 맞춘다.
  뒷줄 유닛의 머리 높이만 위쪽에 따로 확보한다 (앞줄이 커지는 방향은
  화면 안쪽이라 잘리지 않는다)

### 3.3.2 말 위의 배지

말 머리 위에 **성급 별 + 체력 바**를 한 장으로 그린다 (캔버스 스프라이트).
별 개수와 색이 성급마다 다르고 체력은 매 프레임 바뀌므로 이미지 몇 장으로는 안 된다.

- 별 색은 오토체스·TFT 관례대로 **동 → 은 → 금**
- 체력 바 **테두리도 같은 성급 색**이다. 멀어서 별을 못 셀 때도 색은 읽힌다
- 배치 단계에는 체력 바 없이 별만, 그것도 **2성 이상만** 띄운다.
  아홉 마리 전부에 별이 뜨면 정작 2·3성이 안 보인다

### 3.3.3 말 크기

크기는 세 가지가 곱해 정해진다.

1. **부분 정규화.** 모델을 전부 같은 폭으로 맞추면 원본이 작은 모델일수록 더
   크게 늘어난다 — 젤리 마법사(원본 1.97)가 1.32배 늘고 예티(4.65)가 0.56배로
   줄어, 마법사가 탱커만 해진다. 정규화 배율을 지수 0.78 로 눌러 생물 고유의
   크기 차이를 남긴다
2. **직업 배율** (`combat.json > classScale`). 탱커 1.12, 마법사 0.88 —
   직업이 곧 역할이니 실루엣으로 읽혀야 한다
3. **성급 배율** 1성 0.84 / 2성 1.0 / 3성 1.16

결과(칸 폭 2.0 기준): 탱커 평균 2.81, 마법사 2.05, 최대 2.90.

### 3.3.4 원거리 투사체

사거리 2 이상인 말이 때리면 투사체가 날아간다. 마법은 보라, 활은 호박.
피해는 로그가 이미 정했으므로 **순수하게 눈에 보이라고** 있는 것이다 —
안 쏘면 멀리 있는 말이 왜 죽는지가 화면에 없다. 도착 시점이 판정 시점과
조금 어긋나도 상관없다.

### 3.3.1 판의 분위기

판만 놓으면 허공에 뜬 격자로 보인다. 바깥을 세 겹으로 두른다:

| 띠 | 내용 |
|---|---|
| 전장 | **직사각 단상** 하나. 위에 벌집을 옅게 긋는다 — 내 절반은 청록, 상대 절반은 회백색 |
| 대기석 | 단상 **바깥** 앞뒤에 정사각형 9칸씩. 겹치면 어디까지가 전장인지 흐려진다 |
| 해자 (1칸) | 물 타일. 수련·수초. 여기까지가 전장이라는 경계 |
| 물가 (2칸) | 어둡게 누른 풀 타일 + 나무·바위. 판이 도드라진다 |

물가는 판보다 0.34 낮춰 전장을 고원으로 만든다. 하늘은 three 의 단색 배경 대신
**CSS 그라디언트**를 깔고 캔버스를 투명하게 둔다 — 안개 색을 그 중간 톤에 맞췄다.

장식 위치는 시드 고정 난수로 정한다. 새로고침마다 나무가 옮겨 다니면 같은 판이
다른 장소처럼 보인다.

UI 프레임·버튼·육각 칸은 Kenney UI Pixel Adventure (CC0) 32px 타일을
9-슬라이스(`border-image`)로 늘려 쓴다. 인덱스가 `tile_00NN` 뿐이라
`tools/ui-map.json` 에서 이름을 붙인다 — 코드에 숫자를 박으면 나중에
어느 게 무슨 프레임인지 알 수 없다.

### 3.4 조작

| 동작 | 입력 |
|---|---|
| 구매 | 상점 카드 누르기 |
| 배치 · 이동 | 벤치 ↔ 보드 끌기 (차 있으면 자리 맞바꿈) |
| 판매 | 상점 바로 끌기 |
| 정보 보기 | 말을 **탭** — 끌면 배치, 탭하면 정보. 움직인 거리로 가른다 |
| 사거리 보기 | 탭과 동시에 닿는 칸이 호박색으로 켜진다 |

대기석도 3D 다. 아이콘 줄로 두면 3D 말과 2D 칸이 따로 놀아 "들고 있는 말을
판에 올린다"는 느낌이 안 산다. 집기·놓기는 전부 레이캐스트 한 경로로 처리한다.

건너편 대기석에는 **이번 라운드 상대**가 서 있다. 편성을 전투와 같은 시드로
뽑으므로 여기 보이는 말이 실제로 나오는 말이다.

대기석 말은 판 위보다 작게(0.72배) 세운다. 같은 크기면 칸보다 넓어 서로 겹치고,
판에 올린 말과 대기 중인 말이 구분되지 않는다.

카메라는 **판과 대기석만** 담는다. 해자·물가까지 담으려고 물러나면 말이 점만
해져 판이 재미없어진다 — 물가는 배경이지 정보가 아니다.

머리 높이 여유는 **말이 실제로 서는 가장 먼 자리**에만 준다. 배치에서는 상대
절반이 비어 있는데도 판 맨 뒷줄에 최대 키를 잡으면, 아무것도 없는 하늘을
비우느라 전투 화면보다 한참 멀어진다.
| 리롤 · 레벨업 | 좌측 버튼 |

벤치는 DOM, 보드는 3D 라 한쪽 방식만으로는 오갈 수 없다. 포인터 좌표로

### 6.1 레벨 = 인구

시작 레벨 3 (3명) → 최대 9 (9명).

|---|---|
| 3→4 | 2 |
| 4→5 | 6 |
| 5→6 | 10 |
| 6→7 | 18 |
| 7→8 | 30 |

## 9. 전투 시뮬레이션

### 9.1 결정론

- **고정 30틱/초**, 정수 연산, 시드 고정 RNG
- 부동소수점을 상태에 저장하지 않는다
- 같은 (시드, 양측 보드) → 항상 같은 결과
- 이 규칙을 나중에 도입하면 전면 재작성이므로 처음부터 강제한다

### 9.2 타겟팅

1. 헥스 거리 기준 최단 적을 선택한다
2. 거리가 동률이면 유닛 인덱스가 낮은 쪽을 선택한다 (결정론 보장)
3. 타겟이 사망하면 즉시 재탐색한다

### 9.3 이동

- 사거리 밖이면 **빈 칸만 밟는 BFS** 로 길을 찾아 첫 걸음을 딛는다.
  목적지는 타겟의 칸이 아니라 **타겟을 때릴 수 있는 칸**(거리 ≤ 사거리)이다
- 탐욕적으로 "가까워지는 인접 칸"만 고르면, 앞을 아군이 막았을 때 후보가 전부
  점유라 그 유닛이 전투가 끝날 때까지 제자리에 굳는다. 돌아갈 길이 있는데도 그렇다
- 길이 아예 없으면 갈 수 있는 칸 중 가장 가까워지는 쪽으로 한 칸 간다 —
  벽(아군)은 다음 틱이면 열릴 수 있으므로 여기서 굳으면 안 된다
- **한 칸에 `moveInterval` 틱이 든다** (기본 9 = 0.3초). 공격 쿨다운과 같은
  방식으로 건다. 이게 없으면 틱마다 한 칸씩 초당 30칸을 움직여, 판을 0.2초에
  가로지르고 화면에서는 순간이동으로 보인다

### 9.4 사거리

| 직업 | 사거리 |
|---|---|
| 수호자 · 검사 · 불사 | 1칸 |
| 사수 · 술사 | 3칸 |
| 암습 | 1칸 (전투 시작 시 적 최후열로 도약한 뒤) |

### 9.5 마나 · 스킬

- 시작 마나: 유닛별 0~30
- 공격 시 +10
- 피격 시 받은 피해의 1%. **1회 피격당 최대 +20** (누적 상한이 아니다)
- 100 도달 시 스킬 발동, 발동 후 0으로 초기화
- 유닛당 스킬 1개, 타입은 `단일 · 광역 · 버프 · 소환` 4종

## 10. 비동기 PvP (스냅샷)

### 10.1 원리

매 라운드 종료 시 자신의 보드를 서버에 저장한다.

```json
{
  "round": "3-2",
  "level": 6,
  "units": [{ "id": "hero_knight", "star": 2, "hex": [1,3], "items": ["steel_sword"] }],
  "traits": { "kingdom": 4, "guardian": 3 }
}
```

다른 플레이어는 이 스냅샷을 상대로 불러와 싸운다. 상대는 접속해 있을 필요가 없다.

### 10.2 가상 로비

런 시작 시 **비슷한 랭크대의 스냅샷 7개**를 불러와 각각 HP 40을 부여한다. 매 라운드 8명이 서로 붙는 것처럼 시뮬레이션하며, 탈락과 등수가 그대로 나온다.

오토체스는 전투 중 조작이 없으므로 상대가 실시간이든 스냅샷이든 행동이 동일하다. 이 장르가 비동기에 적합한 이유다.

### 10.3 유닛 풀 연동

불러온 7개 스냅샷이 보유한 유닛을 전역 풀에서 차감한다. 이로써 "남이 쓸어가서 안 뜬다"는 경쟁 감각이 재현된다.

### 10.4 초기 데이터

유저가 없는 초기에는 **봇 스냅샷을 시드 데이터로 채운다.** 랭크 구간별로 사전 제작한 보드 세트를 `data/seed-snapshots.json` 에 둔다.

### 11.1 원칙

> **판에 영향을 주는 것은 절대 판매하지 않는다.**

유닛 · 시너지 · 리롤 할인 · 시작 골드 · HP — 하나라도 팔면 비동기 PvP가 무너진다. 상대 스냅샷과 싸우는 구조라 유불리가 즉시 감지된다.

### 11.2 판매 대상 (전량 코스메틱)

| 층 | 상품 |
|---|---|
| 시즌 패스 (주력) | 6~8주 시즌. 무료 트랙 + 유료 트랙. 보상 전량 코스메틱·칭호 |
| 코스메틱 상점 | 유닛 팔레트 스킨 · 보드 스킨 · 승리 연출 · 아바타/프레임 |
| 1회성 소액 | 광고 제거 · 스타터 팩 |

**유닛 팔레트 스킨**이 핵심 상품이다. 셰이더 색조 치환 하나로 스프라이트 1장에서 스킨 20종이 나온다. 비동기 PvP라 내 스킨이 상대 화면에 표시되므로 과시 동기가 성립한다.

### 11.3 광고 지면 2개

| 지면 id | 위치 | 판 영향 |
|---|---|---|
| `run_reward_double` | 런 종료 화면. 획득 재화 2배 | 없음 (등수 확정 후) |
| `daily_chest` | 일일 무료 상자 | 없음 |

부활·무료 리롤 같은 지면은 만들지 않는다.

> `showRewarded` 에 `timeoutMs` 를 넘기지 않는다. 클라이언트가 끊으면 광고를 끝까지 본 유저가 보상을 받지 못하고, 그 판정을 클라이언트가 쥐게 되어 조작 창구가 된다. 모든 호출은 `net/ads.js` 창구를 거친다.

### 11.4 메타 진행

```
런 종료 → 등수 → ① 랭크포인트  ② 패스 경험치  ③ 코스메틱 재화
```

- 유닛 26종 · 시너지 11종은 처음부터 전원 공평하다. 해금이 없다
- 영구 해금 대상은 코스메틱 · 칭호 · 도감뿐이다
- 신규 유저가 기존 유저와 동일한 전력으로 시작하므로 비동기 매칭이 공정하다

### 11.5 데일리 · 주간 미션

패스 경험치 획득 창구이자 조합 다양성 유도 장치다.

예: "시너지 3종 동시 활성" · "3성 유닛 1개 완성" · "야생 4 활성으로 1승"

특정 최적 조합만 반복하는 것을 막는다.

## 12. 기술 아키텍처

### 12.1 디렉터리

```
reroll-royale/
├─ vite.config.js              root: 'game', @sim → 저장소 루트의 sim/
├─ vitest.config.js            **별도 파일.** vite 쪽 root:'game' 을 물려받으면
│                              테스트를 하나도 못 찾고 조용히 통과한다
├─ art-src/                    원본 팩 (빌드 제외)
├─ tools/                      validate.mjs · build-assets.mjs · verify-model-map.mjs
├─ sim/                        **순수 규칙.** DOM·fetch·Math.random 없음
│  ├─ combat.js  hex.js  targeting.js  movement.js  damage.js  skills.js
│  ├─ stats.js   traits.js  modifiers.js  rng.js  data.js
│  └─ pool.js    roster.js   economy.js   rounds.js
├─ tests/                      sim/ 과 1:1
└─ game/                       Vite root
   ├─ index.html               배치·전투 두 화면의 껍데기
   ├─ public/data/             게임 규칙 단일소스 (런타임 fetch)
   ├─ public/assets/           빌드 산출 glTF (tools/build-assets.mjs 가 채운다)
   └─ src/
      ├─ main.js               부팅 · 라운드 진행 · 화면 전환
      ├─ prep.js               배치 · 상점
      ├─ battle.js             전투 로그 재생
      ├─ scene3d.js            두 화면이 공유하는 3D 씬
      ├─ board3d.js            타일 → 월드 좌표
      └─ thumbs.js             유닛 초상화 (모델을 오프스크린 렌더)
```

`sim/` 은 저장소 루트에 둔다. 클라이언트·서버·테스트가 함께 쓰므로
`game/src/` 안으로 넣으면 서버가 클라이언트 디렉터리를 거슬러 import 해야 한다.

`game/public/` 은 가공 없이 복사된다. `data/` 를 여기 두는 이유가 핵심이다 — 런타임에 `fetch` 로 읽으므로 JSON만 고쳐 배포할 수 있다. `import` 로 바꾸면 번들에 박혀 그 길이 막힌다. 코드에서는 절대경로(`/assets/...`, `/data/...`)로 참조한다.

### 12.3 모듈 경계

| 모듈 | 책임 | 의존 |
|---|---|---|
| `core/data` | JSON 로드·캐시. 다른 모듈은 여기로만 규칙을 읽는다 | 없음 |
| `core/store` | 런 상태(골드·레벨·보드·벤치) 보관. 순수 데이터 | `core/bus` |
| `sim/combat` | **순수 함수.** (시드, 보드A, 보드B) → 전투 로그. DOM·Pixi 의존 없음 | `core/data` |
| `view/board` | 전투 로그를 재생만 한다. 전투 판정을 하지 않는다 | `sim/combat` 출력 |
| `net/snapshot` | 스냅샷 저장·조회 | `net/backend` |
| `net/ads` | 보상형 광고 단일 창구 | `net/backend` |

**핵심 경계: 전투 판정과 렌더를 분리한다.** `sim/combat` 이 전투 로그를 만들고 `view/board` 는 그것을 재생만 한다. 이 분리 덕에 헤드리스 밸런스 시뮬레이션과 서버 검증이 같은 코드로 가능하다.

### 12.4 검증 도구

`tools/validate.mjs` 가 검사할 불변식:

1. `shop.json` 각 레벨의 티어 확률 합 = 100
2. 모든 유닛이 종족 1개 + 직업 1개를 정확히 보유
3. 각 시너지의 보유 유닛 수 ≥ 최대 활성 단계
4. 각 시너지에 T1 진입점이 존재 (야생 제외 규칙 없음 — 전 시너지 필수)
5. 티어별 종수와 `shop.json` 풀 매수 정의가 일치
6. 3성 필요 매수(9) > T5 종당 풀 매수(8) — T5 3성 봉쇄 확인
7. 아이템·스킬이 참조하는 스탯 키가 실재
8. 에셋 경로가 실제 파일과 일치 (`tools/audit.mjs`)
