# 결과판 광고 — 계획

2026-09-07. 설계서(8/31) §11.3 의 `run_reward_double` 지면.

## 무엇

결과판 나가기 옆에 "광고 보고 패스 경험치 2배" 버튼. 광고를 끝까지 보면
이번 판이 준 패스 경험치를 한 번 더 받는다. 판에는 손대지 않는다 — 등수가
확정된 뒤의 덤이다.

## 어디에 무엇

| 자리 | 일 |
|---|---|
| `sim/ads.js` | 지면 표(`PLACEMENTS`)와 지급 규칙(`adReward`). 순수 함수 — 서버가 이걸로 판정한다 |
| `server.ts claimAdReward` | 지면 id 와 requestId 만 받는다. 등수·판·하루 상한은 서버가 아는 값. `(계정, requestId)` 를 `adGrants` 에 적어 같은 광고로 두 번 못 받는다 |
| `verifyAd` | ads-verifier 에 묻는다. `verified` 면 준다. `unverified` 면 거절. 닿지 않거나 fetch 가 없으면 **준다** — 지급물이 패스 경험치라 값이 낮고, 끝까지 본 사람을 거절하는 쪽이 더 나쁘다. 젬을 붙이는 날 이 분기를 거절로 바꾼다 |
| `result.js` | 버튼. SDK(`window.Verse8Ads`)가 없으면 안 뜬다. `unsupported_env` 면 세션 동안 숨긴다. `busy` 면 비활성. 받은 뒤엔 `+N 경험치` 로 굳는다 |
| `index.html` | SDK 를 CDN `@latest` 로 |

## 규칙

- 지급량은 서버 표가 정한다. SDK 의 `result.reward` 는 화면 힌트다
- 한 판에 한 번, 하루 3번(`dailyCap`). 상한이 없으면 광고로 패스를 하루에 끝낸다
- 사용자 클릭으로만 튼다. 자동 재생은 정책 위반이다

## 확인

- 순수 규칙: `tests/ads.test.js` 8개
- 서버: 모르는 지면 · 등수 없는 판 · 잘못된 requestId 거절
- 화면: 로컬에서는 SDK 가 `unsupported_env` 를 주거나 아예 없다 — 버튼이 숨는
  것까지만 본다. 실제 지급은 배포본에서 한 판 끝내고 본다
